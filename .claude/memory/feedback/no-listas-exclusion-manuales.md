# No usar listas de exclusión hechas a mano al empaquetar/copiar el proyecto a otro sitio

**Qué pasó (2026-08-27):** al empaquetar este proyecto en un `.tar.gz` para subirlo por SFTP a un servidor del CPD del Ayuntamiento (`10.158.0.3`), se escribió una lista de exclusión de `tar` "a ojo" (`--exclude=node_modules --exclude=.git --exclude=.next ...`) en vez de reutilizar las exclusiones ya definidas en `.gitignore`/`.dockerignore`. Esa lista manual se olvidó de `.mcp.json`, que SÍ está en `.gitignore` (patrón `*.mcp.json`) pero SÍ existe en disco localmente (no está trackeado en git, pero está presente). `.mcp.json` contiene un `SUPABASE_ACCESS_TOKEN` (token de gestión del proyecto Supabase, no el anon/service_role key de la app).

**Consecuencia:** el archivo con el token viajó al servidor remoto, quedó en `/opt/webfotos/.mcp.json` con permisos `644` (legible por cualquier otro usuario de esa máquina compartida) y además quedó momentáneamente incrustado en una capa de caché de build de Docker (`COPY . .` en el Dockerfile lo copió antes de que se detectara el problema).

**Remediado en la misma sesión:** se borró el archivo del servidor, se purgó toda la caché de build de Docker (`docker builder prune -af`) para eliminar la capa que lo contenía, y se confirmó con `grep -r` que no quedaba rastro del token en el directorio desplegado. Se recomendó al usuario rotar ese token de todas formas, por haber salido de su equipo hacia una máquina de terceros aunque ya esté limpiado.

**Regla a seguir siempre a partir de ahora, en cualquier proyecto:** cuando haya que empaquetar/copiar el código de un proyecto hacia fuera (tarball para deploy, `rsync`, adjuntar a un ZIP, etc.), la lista de exclusión debe **derivarse de los archivos `.gitignore`/`.dockerignore` que ya existen en el repo**, nunca escribirse de memoria. Si el proyecto no tiene `.dockerignore`, usar `git ls-files` (respeta `.gitignore` automáticamente) en vez de `tar`/`cp` recursivo sobre el directorio completo — así cualquier archivo gitignored-pero-presente-en-disco (configs locales de MCP, `.env*`, cachés con credenciales) queda excluido por defecto sin tener que acordarse de cada caso.
